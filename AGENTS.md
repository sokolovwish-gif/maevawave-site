# AGENTS.md

## Project

MAEVAWAVE public landing site and lightweight admin backend for yacht trips.

Primary workspace: `/Users/maxim/Documents/Сайт Maevawave`.

The live site is `https://maevawave.ru/`. The payment bot is served separately at `https://pay.maevawave.ru/`, but the site submits lead forms to the bot through an internal relay.

## Repository Layout

- `index.html`, `styles.css`, `script.js` - public landing page.
- `trip.html`, `trip.css`, `trip.js` - individual trip page.
- `lead-form.css`, `lead-form.js` - client-side lead form modal.
- `admin/` - Node.js admin API and static admin UI.
- `images/` - public image assets and logos.
- `legal.html`, `privacy.html`, `robots.txt`, `sitemap.xml`, favicon files - legal/SEO/static support files.
- `deploy/` - deployment notes and edge Caddy snapshot.
- `work/maeva-wave-pay-bot/` - separate nested Git repository for the payment bot. Do not add it to this repository as a normal folder.

## Important Safety Rules

- Do not commit secrets, `.env`, service account JSON, private keys, or production passwords.
- `sail_maeva_vps_PRIVATE_KEY` is local-only and must stay untracked.
- Do not deploy or overwrite server files unless the user explicitly asks for deployment.
- When checking the VPS, prefer read-only commands first.
- The Caddy edge container serves multiple projects. Do not overwrite `/opt/edge/Caddyfile` from this repo without first comparing it with production.

## Runtime Architecture

- Static site lives on VPS in `/opt/maevawave-site`.
- Admin backend lives on VPS in `/opt/maevawave-admin`.
- Admin backend container: `maevawave-admin-admin-1`.
- Shared edge Caddy container: `edge-caddy-1`.
- Bot/payment app container: `sail_maeva-app-1`.
- Bot database container: `sail_maeva-postgres-1`.

Site routing:

- `/` and static assets are served from `/opt/maevawave-site`.
- `/admin/` is protected with Caddy Basic Auth.
- `/api/*` is proxied to `maevawave-admin:3000`.
- Admin API reads trips from the bot Google Sheet and merges local site overrides.
- Lead form submissions are first saved by the admin backend, then relayed internally to the bot app for Telegram, Google Sheets, and database delivery.

## Coding Notes

- Prefer existing plain HTML/CSS/JS patterns. There is no frontend build step.
- Keep CSS cache-busting query strings in HTML updated when changing CSS/JS.
- Do not use server-side runtime data as source code. Admin overrides in `/opt/maevawave-admin/data` are production data, not repo config.
- Trip titles intentionally split prepositions: `Яхтенная неделя` / `в Турции`.
- Lead form uses phone as required contact plus optional Telegram username.
- Gallery defaults are generated by country in `admin/server.mjs`; per-trip gallery can be overridden in admin settings.
